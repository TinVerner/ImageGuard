# ImageGuard

ImageGuard — локальное WPF-приложение для защиты цифровых изображений с помощью двух независимых механизмов:

- цифровая подпись RSA PKCS#1 v1.5/SHA-256 строго контролирует целостность бинарного файла;
- невидимый DCT-watermark хранит идентификационный текст внутри изображения.

Проект выполняется в рамках курсовой работы по дисциплине «Защита информации и надежность информационных систем». Solution, проекты, assembly и namespace используют единое название `ImageGuard`.

## Технологии

- C#, .NET 8, WPF;
- MVVM без тяжелого UI-фреймворка;
- `System.Security.Cryptography` для SHA-256 и RSA;
- `System.Text.Json` для `.igsig`;
- стандартные WPF `BitmapDecoder`, `BitmapSource`, `PngBitmapEncoder` и `JpegBitmapEncoder`;
- xUnit для автоматических тестов.

## Критический порядок защиты

1. Загружается исходное изображение.
2. В яркостную компоненту встраивается watermark.
3. Полученное изображение сохраняется в PNG или JPEG.
4. Сохраненный файл повторно загружается для контроля watermark и расчета MSE/PSNR.
5. Считываются **точные байты уже сохраненного файла**.
6. Эти байты подписываются RSA PKCS#1 v1.5 с SHA-256.
7. Подпись и служебные сведения сохраняются в `.igsig`.

Цифровая подпись намеренно создается **после** встраивания watermark и кодирования файла. Подпись промежуточного `BitmapSource` не соответствовала бы окончательным байтам PNG/JPEG.

## Структура

- `ImageGuard/Models`, `Enums` — модели запросов, результатов и статусов;
- `Services` — работа с изображениями, DCT-watermark, криптография, защита,
  проверка и экспериментальные преобразования;
- `ViewModels`, `Views`, `Resources` — MVVM-интерфейс;
- `ImageGuard.Tests` — unit и integration tests.

## DCT-watermark

Изображение переводится из RGB в YCbCr. Watermark изменяет только яркостную плоскость `Y`; альфа-канал сохраняется. Обрабатываются полные неперекрывающиеся блоки 8×8, один блок хранит один бит.

Перед прямым DCT выполняется level shift `Y - 128`. Бит задается отношением среднечастотных коэффициентов:

- `1`: `DCT[2,3] - DCT[3,2] >= Delta`;
- `0`: `DCT[2,3] - DCT[3,2] <= -Delta`.

Коэффициенты изменяются симметрично относительно их среднего. Используется одно фиксированное значение `Delta`, доступное в интерфейсе; по умолчанию `Delta = 10`. Постоянный запас `25` при записи компенсирует уменьшение разности после IDCT, округления RGB и повторного DCT; правило чтения остается строго `±Delta`. Запас не является адаптивным и одинаков для всех блоков. После IDCT выполняется обратное преобразование YCbCr → RGB. Пиксели вне реально использованных блоков, включая неполные правый и нижний края, восстанавливаются из исходного BGRA32-буфера без лишнего YCbCr round-trip. Извлечение является blind: исходное изображение не требуется.

### Payload

Биты записываются MSB-first. Формат намеренно минимален:

- длина UTF-8 текста в байтах — 32 бита, беззнаковое число Big Endian;
- UTF-8 байты текста — переменная длина.

Один бит занимает один полный блок 8×8. Поэтому требуемая емкость равна `32 + UTF8Length × 8` бит. Если полных блоков недостаточно, встраивание завершается понятной ошибкой без обрезания текста. Отдельных magic, версии payload и контрольной суммы нет.

## Цифровая подпись и `.igsig`

RSA используется только для подписи, не для шифрования изображения. Закрытый ключ сохраняется в PKCS#8 PEM (при заданном пароле — AES-256-CBC через штатный `ExportEncryptedPkcs8PrivateKeyPem`), открытый — SubjectPublicKeyInfo PEM.

`.igsig` — JSON версии 3:

```json
{
  "version": 3,
  "algorithm": "RSA-SHA256-PKCS1-v1_5",
  "hashAlgorithm": "SHA-256",
  "keySize": 2048,
  "createdUtc": "2026-09-26T12:00:00+00:00",
  "protectedFileName": "photo_protected.png",
  "sha256": "...",
  "signatureBase64": "...",
  "publicKeyFingerprint": "AA:BB:...",
  "watermarkDelta": 10
}
```

Поле `sha256` служит для отображения и диагностики. Подлинность определяется только настоящим `RSA.VerifyData`, а не сравнением строки хеша.

Коэффициенты и размер блока фиксированы алгоритмом, поэтому для воспроизводимого извлечения сохраняется только `watermarkDelta`. Старые несовместимые `.igsig` отклоняются с понятным статусом формата. RSA подписывает точные байты изображения, а не JSON-манифест, поэтому поля `.igsig` являются служебными метаданными и должны передаваться вместе с доверенным открытым ключом.

## Независимая проверка

RSA и watermark всегда проверяются отдельными ветвями. Неверная RSA-подпись, отсутствующий или поврежденный `.igsig`, неверный Base64, неподдерживаемая версия и ошибка public key не блокируют попытку извлечения watermark, если изображение декодируется. Несовпадение fingerprint означает «подпись не проверена», а не «изображение изменено». Watermark отдельно сообщает `FOUND`, `NOT FOUND` или `EXTRACTION ERROR`.

## Запуск

Требуется Windows и .NET 8 SDK (или более новый SDK с установленным .NET 8 Desktop Runtime).

```powershell
dotnet restore ImageGuard.slnx
dotnet build ImageGuard.slnx
dotnet run --project ImageGuard/ImageGuard.csproj
```

Тесты:

```powershell
dotnet test ImageGuard.slnx
```

## Ручной сценарий

### 1. Создание ключей

1. Открыть «RSA-ключи».
2. Указать имя, папку и пароль.
3. Оставить размер 2048 бит.
4. Нажать «Создать новую пару ключей».
5. Будут созданы `name.private.pem` и `name.public.pem`; интерфейс покажет fingerprint.

### 2. Защита изображения

1. Открыть «Защита изображения» и выбрать PNG/JPEG.
2. Ввести, например, `BSTU-TEST-001`.
3. Выбрать private PEM и ввести его пароль.
4. Оставить `Delta = 10` либо изменить его для эксперимента.
5. Выбрать файл результата. Путь `.igsig` будет сформирован рядом.
6. Нажать «Защитить изображение».
7. Проверить SHA-256, MSE, PSNR, время и статус контрольного извлечения.

### 3. Проверка

1. Открыть «Проверка изображения».
2. Выбрать защищенное изображение, соответствующий `.igsig` и public PEM.
3. Нажать «Проверить».
4. Для неизмененного файла подпись и watermark должны быть действительны.
5. После изменения или перекодирования файла подпись должна стать недействительной; watermark все равно извлекается независимо и может сохраниться либо повредиться.

### 4. Экспериментальное исследование

1. В разделе «Исследование» выбрать защищенное изображение, исходный `.igsig` и открытый ключ.
2. Указать папку результатов и ожидаемый текст watermark, если требуется BER.
3. Выбрать преобразование и параметр либо запустить предустановленную серию.
4. Программа сохранит фактические преобразованные файлы и для каждого независимо рассчитает статус подписи, watermark, MSE, PSNR, BER и время.
5. Экспортировать результаты в CSV.

Поддержаны JPEG-сжатие, яркость, контрастность, гауссов шум с воспроизводимым seed, resize, центральный crop и закрашивание прямоугольной области. После resize/crop можно вернуть изображение к исходному размеру билинейной интерполяцией. Если размеры результата отличаются, MSE/PSNR выводятся как `N/A`. MSE считается по RGB без alpha; при MSE=0 PSNR равен `+Infinity`. BER сравнивает исходные решения DCT-битов с ожидаемой последовательностью `[длина + UTF-8]`; при невозможности сравнения выводится `N/A`.

Длительные операции показывают определенный progress и поддерживают отмену. Отмена отображается как отдельный пользовательский результат, а не как ошибка проверки.

## Ограничения

- watermark пока использует последовательный порядок блоков без повторения и ECC;
- простой payload не содержит magic или контрольной суммы, поэтому повреждение определяется по невозможной длине, неоднозначным коэффициентам или некорректному UTF-8, но не гарантированно для любой комбинации ошибок;
- устойчивость к JPEG, шуму и геометрическим преобразованиям не гарантируется и должна измеряться;
- JPEG всегда теряет alpha; PNG сохраняет alpha без изменений;
- EXIF/metadata не сохраняются как обязательная часть pipeline;
- без PKI или доверенного канала нельзя установить совместную подмену изображения, `.igsig` и открытого ключа;
- watermark предназначен для идентификационной информации и не гарантирует криптографическую целостность.
