# ImageGuard

Локальное WPF-приложение для защиты цифровых изображений. Используются два независимых механизма:

- цифровая подпись RSA PKCS#1 v1.5 / SHA-256 проверяет целостность байтов файла;
- невидимый DCT-watermark хранит идентификационный текст внутри изображения.

Курсовой проект по дисциплине «Защита информации и надежность информационных систем».

Разделы интерфейса:

1. Защита изображения — встраивание ЦВЗ и создание `.igsig`;
2. Проверка изображения и Исследование — пункты меню без экрана;
3. RSA-ключи — создание и просмотр PEM-пары 2048 бит.

## Технологии

- C#, .NET 8, WPF;
- экраны на code-behind без MVVM;
- `System.Security.Cryptography` для SHA-256 и RSA;
- `System.Text.Json` для `.igsig`;
- стандартные WPF `BitmapDecoder` и `PngBitmapEncoder`;
- xUnit.

## Порядок защиты

1. Загружается исходное изображение.
2. В яркостную компоненту встраивается watermark.
3. Изображение сохраняется в PNG.
4. Сохранённый файл повторно загружается: контрольное извлечение ЦВЗ.
5. Считываются **точные байты уже сохранённого файла**.
6. Эти байты подписываются RSA PKCS#1 v1.5 с SHA-256.
7. Подпись и служебные сведения сохраняются в `.igsig`.

Подпись создаётся **после** встраивания watermark и кодирования файла. Промежуточный `BitmapSource` не подписывается.

## DCT-watermark

Изображение переводится из BGRA в YCbCr (BT.601). Watermark изменяет только плоскость `Y`; альфа-канал сохраняется. Обрабатываются полные неперекрывающиеся блоки 8×8, порядок row-major, один блок хранит один бит.

Перед DCT выполняется level shift `Y - 128`. Бит задаётся отношением среднечастотных коэффициентов `F(2,3)` и `F(3,2)`:

- `1`: `F(2,3) - F(3,2) >= Delta`;
- `0`: `F(2,3) - F(3,2) <= -Delta`.

Коэффициенты изменяются симметрично относительно среднего. `Delta` задаётся в интерфейсе, по умолчанию 10. При записи используется постоянный запас `Delta + 25`, чтобы компенсировать IDCT, округление RGB и повторный DCT. Правило чтения остаётся строго `±Delta`. Запас не адаптивный. После IDCT выполняется YCbCr → BGRA. Пиксели вне использованных блоков, включая неполные края, копируются из исходного BGRA32 без лишнего round-trip. Извлечение blind: исходное изображение не нужно.

### Payload

Биты записываются MSB-first:

- длина UTF-8 текста в байтах — 32 бита, беззнаковое Big Endian;
- UTF-8 байты текста.

Требуемая ёмкость: `32 + UTF8Length × 8` бит. Если полных блоков недостаточно, встраивание завершается ошибкой без обрезания текста. Magic, версии payload и контрольной суммы нет.

## Цифровая подпись и `.igsig`

RSA используется только для подписи, не для шифрования изображения. Закрытый ключ — PKCS#8 PEM, открытый — SubjectPublicKeyInfo PEM. Размер ключа — 2048 бит.

`.igsig` — JSON версии 3:

```json
{
  "version": 3,
  "algorithm": "RSA-SHA256-PKCS1-v1_5",
  "hashAlgorithm": "SHA-256",
  "keySize": 2048,
  "createdUtc": "2026-09-26T12:00:00+00:00",
  "protectedFileName": "photo_protected.png",
  "sha256": "...",
  "signatureBase64": "...",
  "publicKeyFingerprint": "AA:BB:...",
  "watermarkDelta": 10
}
```

Поле `sha256` — диагностика. Подлинность определяется `RSA.VerifyData`, а не сравнением строки хеша. Fingerprint — SHA-256 открытого ключа в формате SPKI, hex через двоеточие. Для извлечения ЦВЗ из `.igsig` берётся `watermarkDelta`. RSA подписывает байты изображения, а не JSON.

## Запуск

Нужны Windows и .NET 8 SDK.

```powershell
dotnet restore ImageGuard.slnx
dotnet build ImageGuard.slnx
dotnet run --project ImageGuard/ImageGuard.csproj
```

Тесты:

```powershell
dotnet test ImageGuard.slnx
```

## Ручной сценарий

### 1. Создание ключей

1. Открыть «RSA-ключи».
2. Указать имя и папку.
3. Нажать «Создать новую пару ключей».
4. Будут созданы `name.private.pem` и `name.public.pem`; интерфейс покажет fingerprint.

### 2. Защита изображения

1. Открыть «Защита изображения» и выбрать PNG.
2. Ввести текст водяного знака, например `BSTU-TEST-001`.
3. Выбрать private PEM.
4. Оставить `Delta = 10` или изменить его.
5. Выбрать файл результата. Путь `.igsig` формируется рядом.
6. Нажать «Защитить изображение».
7. Проверить SHA-256 и статус контрольного извлечения.

Длительные операции показывают progress.

## Ограничения

- watermark использует последовательные блоки без повторения и ECC;
- payload без magic и контрольной суммы: повреждение видно по невозможной длине, неоднозначным коэффициентам или некорректному UTF-8, но не для любой ошибки;
- устойчивость к JPEG-сжатию, шуму и геометрии не гарантируется;
- PNG сохраняет alpha;
- EXIF не является частью pipeline;
- без доверенного канала нельзя обнаружить совместную подмену изображения, `.igsig` и открытого ключа;
- watermark не заменяет криптографическую целостность.
